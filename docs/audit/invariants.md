# Инварианты переключения AFRd2

Формулировки, которые должны быть верны при любых настройках и любом плеере. Для каждого —
текущий статус по итогам аудита (`docs/audit/report-2026-11.md`), чем проверяется и что
нарушается при отказе. Статус «держится» означает: проверено чтением кода и, где возможно,
живым прогоном; статус «нарушается» — есть воспроизведение; «не проверяется» — нет способа
убедиться без нового кода или лога.

## Как это будет проверяться (следующий шаг, Task 5 плана)

1. `seq_step (struct seq_state *, enum seq_event, struct seq_out *)` — чистая функция без sysfs и
   реального времени: состояния `нет видео / мерим / решение есть / переключили / ждём
   подтверждения / повторили / сдали / держим`, события из списка инвариантов.
2. Фикстуры — последовательности из `~/AI/afrd.log` (тестер 03.11), `~/AI/afrd1.log` (1.0.0) и
   стендовых логов `.50`; каждая фикстура имеет ожидаемое число переключений и ожидаемые строки
   решений.
3. Тест падает на текущем коде (I1: 4 цикла вместо 1; I2: переключение после сдачи; I3: запись
   формата до сверки), проходит после правок. Инварианты I4, I10, I15 закрываются уже
   существующими host-тестами (`test_guard.c`, `test_fps_env.c`), их достаточно связать с ID.
4. Живые проверки, которые нельзя заменить тестом, выписаны в отчёте (раздел «Не проверено»).
