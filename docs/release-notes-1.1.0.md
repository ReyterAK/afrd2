# AFRd2 1.1.0

Первый выпуск после 1.0.0. Заявка прежняя: **Android 11–14 (Amlogic)**; старый путь
(Android 6–9) не изменён.

## Главное: «зажим» частоты побеждён

Плеер запоминает частоту экрана в начале сессии проигрывания и внешнюю смену режима не
перечитывает: ролик, начатый при 50 Гц, после переключения на 60 продолжал отдавать
~50 к/с, и картинка оставалась задёрганной до перезапуска ролика. Измерено по подаче
видео-слоя: 49.4 против 59.94 к/с.

Теперь демон:

* поднимает режим до максимума, который поддерживает ТВ, ещё **до первого кадра** плеера
  (`switch.bump`), в том числе сразу по исчезновению канала декодера при смене ролика и по
  выходу плеера на передний план (`switch.bump.on.app`);
* если переключение всё же пришлось на живое видео, **сбрасывает «потолок» частоты**
  (`switch.ceiling.reset`): перезапуском процесса кодека, а при его отказе — сменой
  плотности экрана.

Живые замеры: ATV14 — 50.34 → 59.94 к/с, провал подачи 83 мс; Android 11 — 50.02 → 59.94 к/с
за 0.26 с с сохранением позиции ролика.

**Цена:** перезапускается HAL кодека, поэтому фоновое воспроизведение в другом приложении
прервётся.

## Что ещё изменилось

| | |
|---|---|
| Сброс «потолка» | `switch.ceiling.method`: `auto` (перезапуск кодека, при отказе — плотность), `codec`, `density`. Перезапуск кодека: декодер пропадает на 68 мс и возвращается на 1.1 с (смена плотности стоила 6.8 с и перезапускала Activity) |
| Android 10/11 | постоянный помощник смены режима (`vendor.disp.persist`): смена 0.34–1.09 с вместо 0.85–1.76 с |
| Кому применяется зажим | `switch.bump.pkg` — по умолчанию только штатный YouTube; пустой список выключает механики совсем |
| YouTube | больше не исключается из автоподбора (`switch.skip.pkg` пуст); при обновлении настройка переносится сама |
| Android 10/11: показания частоты | приведены к фактическим (59.94 при `frac_rate_policy=1`, 60.00 при 0) |
| Android 10/11: дробность | выставляется по контенту через `frac_rate_policy`: фильм 23.976 больше не играет на 24.000 |
| AV1 | относительная поправка `fps.correct.av1.pct` (по умолчанию выключена) |
| Настройки | «Устранять зажим частоты» (тумблер), «Плееры, которым устранять зажим», «Запрещённые частоты развёртки» и «Формат HDMI» — выбором из списка |

## Исправлено

* Проверка подачи смотрит на слой видео приложения, которому принадлежит декодер, а не на
  первый `SurfaceView`; ожидание берётся от той же частоты, по которой выбран режим;
  «лечение» не повторяется, если первое не изменило подачу.
* Демон перечитывает текущий режим экрана перед решением: ролик 60 к/с не остаётся на 25 Гц,
  если режим сменила системная АПЧ или сам плеер.
* Приложение не падает при запуске на спящем боксе (Android 8–9).
* На стоковых прошивках находится рабочий `su` (было «требуется root» при установленном
  Magisk).
* Ожидание конца видео прерывается появлением нового видео — переключение каналов IPTV не
  тормозит при большой «Задержке остановки».
* Проверка подачи не срабатывает ложно после паузы (интервалы считаются по медиане).
* Журнал: «HDMI not active» — только на реальном событии HDMI.

## Установка

* **APK** — приложение с интерфейсом, внутри оба демона (32- и 64-битный).
* **Magisk-модуль** — то же без приложения, `armeabi-v7a` или `arm64-v8a`. Интерфейса нет:
  настройки в `/data/adb/modules/afrd2/afrd.ini`.
* Оба варианта одновременно держать нельзя: после перезагрузки поднимутся два демона.
