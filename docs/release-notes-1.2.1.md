## AFRd2 1.2.1

Автоподбор частоты обновления HDMI под частоту кадров видео для Amlogic.
Форк [AFRd](https://github.com/anpaza/afrd) 0.3.2 (Андрей Заболотный, anpaza), GPL-3.

### Новое

* **«Формат HDMI»: умолчание — «Не изменять формат».** Пункт «Авто» удалён: он
  обещал «максимум качества», которого демон обеспечить не может (источник видео
  почти всегда 4:2:0 8–10 бит), а фактически при несовпадении правила записывал
  стартовый профиль на всех режимах. Теперь по умолчанию демон не пишет цветовой
  формат вообще: его выбирают система и плеер, включая 4K. В списке остались
  «Не изменять» и по пункту на каждый формат из `dc_cap` телевизора; в каждом
  пункте формата сохранено правило защиты полосы 4K.
* **Перенос старого «Авто».** Если в настройках было выбрано «Авто»
  (`2160p[4-9].*=420`), приложение один раз переводит его в «Не изменять
  формат». Свои правила и другие пункты миграция не трогает. Профили Android 6–9
  не изменились: там остаётся значение `… .*=444` (в GUI — «YUV 4:4:4»).
* **Android 12–14: смена таблицы режимов SurfaceFlinger больше не отменяет
  только что выбранную частоту.** Событие (включение ТВ, смена EDID, рестарт SF)
  обрабатывается сразу; если режим уже применён по новой таблице, удержание не
  снимается. Раньше событие, пришедшее перед стартом видео, обрабатывалось через
  15–20 с — после быстрого решения, — и режим возвращался к исходным 60 Гц
  (на экране 24 → 60 → 24), а уведомление на время замера показывало 0,00 Гц.
  Теперь на время замера показывается фактическая частота дисплея.

### Исправлено

* ЧАВО: разделитель абзацев внутри ответа — пустая строка, а не `!` без текста
  (формат ЧАВО требовал текст после `!`, и проверка `test_faq.sh` была красной).

### Требования и установка

* root (Magisk или встроенный `su` в userdebug-прошивке);
* Amlogic; ядро 5.x — новый путь, ядра 3.14/4.9 — прежний путь AFRd;
* приложение — Android 6.0+ (minSdk 23).

Одновременно должен работать только один экземпляр демона.

* **APK** (интерфейс, настройки, ЧАВО): `ru.reyter.afrd2-1.2.1-release.apk`,
  пакет `ru.reyter.afrd2`. Открыть приложение, дать root и включить автоподбор.
* **Мини-приложение «AFR burst»** (`burstapp-release.apk`, пакет
  `ru.reyter.afrd2.burst`) — необязательное, ставится рядом с APK и служит
  одной кнопкой «сеанс AFR» для мапперов: одна запись в списке приложений, без
  extras и action. Требует установленного AFRd2.
* **Magisk-модуль** (автостарт без приложения): `afrd2-magisk-armeabi-v7a.zip` или
  `afrd2-magisk-arm64-v8a.zip` — Magisk → Модули → «Установить из памяти» →
  перезагрузка. Модуль ничего не пишет в системные разделы.
* **Комплект для ROM-разработчика** (`afrd2-1.2.1-for-rom-dev.zip`): демоны под обе
  ABI, профиль `afrd.ini`, APK и три документа — `integration-rom.md` (встраивание в
  прошивку), `afr-on-demand.md` и `afr-on-demand-answer-to-rom.md`.

Подробности, ограничения и сборка из исходников — в
[README](https://github.com/ReyterAK/afrd2/blob/master/README.md) и
[ЧАВО](https://github.com/ReyterAK/afrd2/blob/master/FAQ-ru.txt).
