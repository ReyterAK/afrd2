[SPOILER=Что нового в версии 1.2.0]
[B]Новое[/B]
- [B]AFR «по требованию».[/B] Обычно автоподбор выключен, а по команде извне демон включается на время сеанса, делает одно переключение, возвращает прежний режим и снова выключается: команда API `burst <мс>`, broadcast `ru.reyter.afrd2.action.BURST`, activity `ru.cobra.afrd.BURST` или утилита `afrd --burst <с>`. Заявка slimBOXtv.
- [B]Проверка фактической частоты после смены режима.[/B] Через 2.5 с демон читает тайминги из `vinfo` и пишет в журнал, что реально получилось на экране: «фактическая частота дисплея: 23.98 Гц (vinfo 23976/1000)». Имя режима одно на пару 23.976/24.000, поэтому раньше проверить было нельзя.
- [B]Сверка источников частоты в журнале.[/B] Если видео-слой обновляется заметно реже решения по счётчику кадров, в журнал идёт одна строка со всеми числами (счётчик, подача, заявленная частота, состояние декодера) — видно, кто ошибается, без догадок.

[B]Изменено[/B]
- [B]«Зажим» после подъёма закрывается за ~5 секунд вместо 14–31.[/B] Пока держится максимальный режим, решение принимается по данным видео-слоя, а не по ожиданию полной огибающей. Живой замер: максимум держался 5.3 с.
- [B]OTT Navigator на Android 10 и новее исключён из AFRd по умолчанию:[/B] он сам управляет частотой через `Surface.setFrameRate`, и подъём/возврат демона с ним только конфликтуют. Если AFR в OTT выключен — перенесите его из «AFR мешает» в «Устранять зажим». На Android 6–9 всё как раньше.
- [B]Списки стали отдельными:[/B] подъём режима — только штатный YouTube, сброс «потолка» — свой список (тоже только YouTube): перезапуск кодека рвёт сессию OTT.
- [B]Проверка подачи[/B] считает долю интервалов-выбросов, а не только медиану: рваная подача больше не проходит как «подача в порядке».
- [B]«Авто» в политике дробных частот стало настоящим:[/B] целая частота берётся только при заявленной целой (подсказка плеера или длительность кадра), иначе остаётся дробный представитель. Мусорные заявки (30 fps при реальных 23.976) игнорируются.
- [B]Настройки без дублей:[/B] поправка AV1 — один пункт «Авто / Выключено», поведение на паузе — один пункт «На паузе»; ключи, не действующие на текущем пути, скрыты, а не погашены.
- [B]Меньше шума в журнале:[/B] повторяющиеся строки («счётчик кадров стоит», «не в switch.bump.pkg») ограничены по частоте.

[B]Исправлено[/B]
- [B]`switch.skip.pkg` не запрещал смену режима[/B] на новом пути с 1.0.0: гейт стоял после быстрого решения, и плеер из списка «AFR мешает» всё равно получал переключение. Теперь для него не работают ни замер, ни быстрое решение, ни перепроверка, ни переприменение.
- [B]Рабочий стол больше не остаётся на частоте видео[/B] у плееров из «Устранять зажим»: возврат режима при выходе плеера с переднего плана снова работает, в том числе при выключенном «возврате при остановке».
- [B]Поправка AV1 применялась дважды,[/B] если были заданы и проценты, и смещение: контент 25.000 измерялся как 24.90. Теперь модель выбирает демон по платформе, старые ключи читаются взаимоисключающе.
- [B]Возврат режима на паузе и остановке[/B] больше не оставляет экран на частоте ролика; на стыке роликов — на одну смену режима меньше.
