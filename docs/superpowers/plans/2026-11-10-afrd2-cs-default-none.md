# AFRd2: цветовой формат — умолчание «Не изменять», пункт «Авто» убирается

> **For agentic workers:** план следующей сессии (`superpowers:subagent-driven-development`
> или `executing-plans`). Отметки `- [ ]`. Обновлён 2026-11-10 после решений владельца
> (журнал §236–§237).

**Goal:**

1. По умолчанию демон **не меняет цветовой формат** (`cs.select` пуст): профиль
   Android 12–14 и умолчание настройки в APK.
2. Пункт **«Авто» удаляется** из настройки «Формат HDMI»: он обещал «максимум
   качества», которого демон объективно не может обеспечить, а фактически
   фиксировал стартовый профиль на всех режимах, где правило не совпало
   (проверено host-прогоном, журнал §236).
3. При обновлении сохранённое значение «Авто» (`2160p[4-9].*=420`) переводится
   в «Не изменять» (пусто) — одноразово, по образцу `Av1Migrate`/`kInertDefaults`.
4. Legacy-профили (Android 6–9) **не меняются** (решение L1): в них остаётся
   `2160p[4-9].*=420 .*=444`, в GUI это существующий пункт «YUV 4:4:4».

**Почему «Авто» убирается (основание, не мнение):**

* источник видео почти всегда 4:2:0 8–10 бит — апскейл в 444/12bit не добавляет
  информации, «больше бит» ≠ «лучше картинка» для видео;
* `dc_cap` — глобальный список форматов/глубин ТВ, **без привязки к режиму**:
  заявленный `444,12bit` для 2160p60 (~26.7 Гбит/с) в полосу HDMI 2.0 (≈18)
  не пролезает; что реально влезет, зависит ещё и от кабеля/линк-тренировки;
* вендорский стек сам выбирает и асинхронно переставляет формат после смены
  режима (поэтому демон и повторяет запись через ~2.5 с) — «авто» демона было
  бы вторым угадыванием поверх первого;
* фактическое поведение пункта: `2160p[4-9].*=420` + при несовпадении правила
  запись стартового профиля (`colorspace.c:515`, `cur_cs = def_cs`).

**Принятые решения (2026-11-10):**

| # | Решение |
|---|---|
| 1 | Legacy — **L1**: профили `afrd-android7-`/`afrd-android8+`/`afrd-minix7-.ini` не трогаем; значение отображается как «YUV 4:4:4», правило защиты 4K внутри (уже описано в ЧАВО) |
| 2 | Пункт «Авто» удаляется из списка и статического набора `CsPolicy` |
| 3 | Миграция: `cs_select` == старый «Авто» (сравнение без учёта пробелов) → пустая строка; любое другое значение не трогаем; флаг в `requisites` |
| 4 | `cur_cs = def_cs` (нет совпадения правила → стартовый профиль) — **код не меняем**, поведение описываем в README (после удаления «Авто» это касается только правил, написанных руками) |
| 5 | Версия выпуска — **открыто** (1.3.0 / 1.2.1), решается в Task 4 |

**Где живут умолчания (дерево `d39f090` + правки плана):**

| Место | Сейчас | После |
|---|---|---|
| `config/afrd2.ini:351` (ATV14-профиль) | `cs.select=2160p[4-9].*=420` | `cs.select=` (пусто) |
| `android/app/src/main/res/xml/preferences.xml:109` | `android:defaultValue="2160p[4-9].*=420"` | `android:defaultValue=""` |
| `config/afrd-{android7-,android8+,minix7-}.ini:29` | `2160p[4-9].*=420 .*=444` | **без изменений (L1)** |
| `android/.../res/raw{,-ru}/afrd_*.ini`, `changelog.txt`, `faq.txt` | генерируются | пересобрать `./mka` |

**Как значение доходит до демона:** `Config.save(prefs)` при первом запуске
засевает префы из профиля; дальше `Config.load(prefs)` перекрывает ими ini и
`condSave()` пишет `afrd.ini` в кэш приложения. Миграция правит префы **до**
`conf.load(mOptions)` — как `resetInertKeys`.

## Global Constraints

* **Стенды не трогать** до отдельного разрешения владельца (окна нет).
* Демон (`afrd.c`, `colorspace.c`) **не меняется**; весь объём — профиль,
  APK/Java и документы.
* Legacy-профили и их поведение — байт в байт как было.
* Host-тесты `sh tests/run_tests.sh` зелёные, предупреждений при сборке нет;
  `./mka` — единственный источник копий в `res/raw*`.
* Миграция — **одноразовая** (флаг в `requisites`), правку, сделанную после
  обновления, не трогаем никогда.

## Review Focus

1. **Миграция не задевает чужие значения:** `2160p[4-9].*=420 .*=444`,
   `… .*=rgb`, `1080p.*=rgb`, `""`, отсутствие ключа — не трогаются; пробелы и
   регистр в старом «Авто» не мешают распознаванию.
2. **Пустое значение выживает во всех писателях:** `IniRewrite` (`cs.select=`),
   `Config.load/save`, `Seed.shouldSeed` (пустое — не умолчание, но здесь это
   осознанное значение настройки, а не «сеять нечего»), `condSave`.
3. **Список без «Авто»:** `CsPolicy.valuesFor` начинается с «Не изменять», по
   пункту на формат из `dc_cap`; статический `VALUES`/`arrays.xml` согласованы;
   `csLabel` не оставляет осиротевших подписей.
4. **Legacy не тронут:** диф `config/afrd-android*.ini` пуст; значение
   legacy-профиля по-прежнему подписано «YUV 4:4:4».
5. **Документы** не обещают ни «Авто», ни «остальные режимы не трогаются»
   (README:1082 сейчас неверен); сказано про миграцию и про legacy.
