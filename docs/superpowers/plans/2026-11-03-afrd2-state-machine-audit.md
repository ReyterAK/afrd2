# Аудит логики переключения AFRd2: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** получить проверяемое описание логики переключения (спека), список инвариантов с тестами и отчёт «запланировано ≠ реализовано» — чтобы каждое следующее изменение можно было проверять, а не отлаживать по логам тестеров.

**Architecture:** три слоя. (1) Спека: таблица «событие × состояние → действие» для автомата переключения, выписанная из журнала §1–§128, ChangeLog и ЧАВО. (2) Код: тот же автомат, вынесенный в чистую функцию со структурой состояния (как уже сделано для `guard_decide`), плюс replay реальных логов тестеров как host-тесты. (3) Отчёт: расхождения спеки и кода с приоритетом и тестом на каждое.

**Tech Stack:** C99 (демон, host-тесты через `cc`), Java (GUI-логика без Android, `javac`), `sh tests/run_tests.sh`, NDK только для сборки артефактов.

**Spec:** `afrd2-journal.md` §1–§128 (поведение «как задумано»), `ChangeLog-ru.txt` 1.2.0, `FAQ-ru.txt`, `docs/release-notes-1.2.0.md`. Отдельного спека-документа нет — его и создаёт Task 2.

## Global Constraints

- Язык документов и комментариев — русский; стиль комментариев в коде — существующий (почему, а не что).
- Поведение по умолчанию не меняется: аудит и вынос логики не должны менять решения демона. Любая правка поведения — отдельный коммит с живой проверкой на стенде.
- Host-тесты обязаны работать без Android и без сети: `sh tests/run_tests.sh` (20 C-наборов + 4 Java).
- Каждый тест — детерминированный, изолированный, без опоры на реальное время (время подаётся параметром).
- Стенды: `.50` (ATV14, 1080p) доступен; `.48` (ATV9) доступен; `.42` (ATV11) в сети отсутствует — вендорный путь живьём не проверяется.
- Никаких «TODO/позже»: незакрытое расхождение попадает в отчёт как открытое, с указанием, чем проверить.

## Review Focus

- **Пауза и конец видео во время переключения.** Пользователь ждёт: пауза не должна ломать замер, а конец ролика — оставлять режим поднятым. Проверяется в Task 5 (replay логов с паузами) и Task 6 (таблица «событие × состояние»).
- **Смена канала в момент замера.** Ожидание: новый ролик начинает замер заново, старое решение не применяется. Task 5.
- **Плеер из `switch.skip.pkg`.** Ожидание: демон не меняет ему режим ни одним путём, но возврат своего удержания делает. Task 4.
- **Неприменённый режим / отказ HAL.** Ожидание: один повтор, затем сдача до конца видео, экран с сигналом. Task 5 (это уже ломалось дважды).
- **Конфиг с недействующим на текущем пути ключом.** Ожидание: ключ не влияет и об этом сказано в логе. Task 4.
- **Смена таблицы режимов SurfaceFlinger во время работы** (hotplug/смена формата). Ожидание: цель перерезолвится, чужой id не уходит в транзакцию. Task 4.

- [ ] **Step 1:** выписать утверждения; для каждого указать текущее место проверки в коде (если есть).

**Acceptance:** ни одного утверждения без способа проверки; тест-заготовка проходит на текущем коде (инварианты выполняются) либо падает и это записано как расхождение.
