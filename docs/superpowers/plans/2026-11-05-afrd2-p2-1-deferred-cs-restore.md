# P2-1: отложенный возврат цветового профиля — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** убрать гонку «возврат режима + запись цветового профиля в одном такте», из-за которой на части конфигураций возврат режима может не примениться, и получить это поведение под host-тестом, не меняя ничего в обычном случае (профиль совпал — записи нет).

**Architecture:** решение «писать профиль сейчас / отложить / выбросить» выносится в чистую функцию (как `guard_decide`/`seq_step`), а в `afrd.c` остаётся только применение: таймер 2.5 с (та же точка, где сейчас пишется формат после прямого переключения), плюс явные точки сброса отложенного — новый ролик, `reconf`, выход демона.

**Tech Stack:** C99 (демон, host-тесты через `cc`), `sh tests/run_tests.sh`; живая приёмка — только на боксе тестера (`cs.select=2160p[4-9].*=420`, 4K, формат `420,12bit`), на `.50` не воспроизводится (framework возвращает `444,12bit` до возврата режима).

**Spec / контекст:** `docs/audit/report-2026-11.md` (P2-1), журнал §190, `afrd.c:2636` (`atv14_restore_mode`), `afrd.c:2612` (комментарий про запись формата, отменяющую переход), `colorspace.c:567` (`colorspace_restore`).

## Global Constraints

- Поведение по умолчанию не меняется: если профиль совпадает с текущим, `colorspace_restore()` остаётся мгновенным no-op (это 100 % случаев на `.50`).
- Никаких новых ключей конфига: правка внутренняя, GUI не трогаем.
- Host-тесты без Android, сети и реального времени: время и состояние передаются параметрами.
- Каждый шаг — отдельный проверяемый результат; без «TODO позже».
- Живая приёмка обязательна до релиза: без лога тестера правка считается условной (как сейчас P2-1).

## Review Focus

- **Обычный случай не замедляется.** Профиль совпал → записи нет, ничего не откладывается, лишних строк в журнале нет.
- **Возврат режима не отменяется.** Профиль отличается → запись уходит на 2.5 с позже транзакции 1035, но не теряется: если новый ролик начался раньше, отложенное сбрасывается без потери сохранённого профиля.
- **Выход и reconf не оставляют «видео-формат» на рабочем столе.** На `afrd_fini`/`reconf` отложенная запись выполняется синхронно.
- **Отказ режима.** Если возврат режима не удался, профиль всё равно возвращается по таймауту (5 с), чтобы рабочий стол не остался в формате видео.

### Task 1: Чистая функция решения

**Files:**
- Create: `csplan.c`, `csplan.h` (или секция в `colorspace.c` — решить по объёму; предпочтительно отдельный файл, как `guard.c`/`seq.c`)
- Test: `tests/test_csplan.c`, добавить в `tests/run_tests.sh`

**Interfaces:**
- Produces:
  ```c
  typedef enum { CS_PLAN_NOW, CS_PLAN_WAIT, CS_PLAN_DROP } cs_plan_t;
  cs_plan_t cs_restore_plan (bool profile_differs, bool mode_settled,
                             bool new_video, bool exiting, unsigned long long elapsed_us);
  ```
- Правила: `!profile_differs` → `CS_PLAN_NOW` (no-op путь, поведение как сейчас);
  `new_video || exiting` → `CS_PLAN_NOW`; `profile_differs && !mode_settled && elapsed_us < 2.5 с` → `CS_PLAN_WAIT`;
  `elapsed_us >= 5 с` → `CS_PLAN_NOW` (страховка); иначе `CS_PLAN_WAIT`.

- [ ] **Step 1:** написать тест первым: 6 случаев из правил выше, включая `mode_settled=true` → `NOW` и таймаут 5 с → `NOW`.
- [ ] **Step 2:** реализовать функцию; прогнать `sh tests/run_tests.sh` (набор `test_csplan`).
- [ ] **Step 3:** зафиксировать в комментарии, почему порог 2.5 с совпадает с точкой записи формата после прямого переключения (`hdrinfo_timer`).
