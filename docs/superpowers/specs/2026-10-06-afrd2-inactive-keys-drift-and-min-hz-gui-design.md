# AFRd2: производные списки недействующих ключей и GUI-строка `mode.min.hz.list`

Дата: 2026-10-06. Статус: спека на ревью владельцу.
Ветка работы: `afrd2-cfgkeys-gui` (от `master` = `e53fb5b`, он же `97c320e` по дереву).

## 1. Что делаем и зачем

Два пункта, открытые после слияния ветки `afrd2-app-picker` (леджер
`.superpowers/sdd/2026-10-06-afrd2-legacy-pkgskip-app-picker/progress.md`, вопросы 1–3):

1. **`mode.min.hz.list` без строки в GUI.** Ключ действует на обоих путях
   (`CFGKEY_BOTH`), README называет его оставшимся средством для плееров, которые
   «зажимают» темп отрисовки, но задать его можно только правкой `afrd.ini` на
   устройстве. Правка профиля **теряется при обновлении APK**: `MainActivity.prepareConfig()`
   сравнивает `afrd_ini_ver` с `mPackageInfo.lastUpdateTime` и при несовпадении заново
   извлекает профиль из ресурсов, перезаписывая файл целиком (`Control.extractConfig`).
   Правки, сделанные через GUI, такого не боятся: `updateConfig()`/`applyPrefs()` грузят
   существующий ini и накладывают поверх него только ключи из `ini_options`.

2. **Списки недействующих ключей в GUI синхронизируются вручную** с таблицей
   применимости `cfgkeys.c` (`k_keys[]`, флаги `CFGKEY_LEGACY`/`CFGKEY_ATV14`/`CFGKEY_BOTH`/
   `CFGKEY_APP`). Рекомендация финального ревью ветки — держать их производными.
   Дрейф уже есть, и он не безобидный (см. §3).

Оба пункта — про одно и то же свойство: **то, что GUI обещает пользователю, должно
совпадать с тем, что делает демон.**

## 2. Не-цели

* `fps.correct.list` («пакет=проценты») на выборщик **не переводится** этой задачей.
  Формально это тот же формат, но семантика другая (проценты поправки, возможны
  отрицательные значения), и у ключа уже есть привычное текстовое поле. Превращение
  его в выборщик — отдельное решение владельца (вопрос выносится в леджер).
* Демон, формат конфига, API (UDP 50505) — не трогаем.
* Значения по умолчанию профилей не меняем (строка `mode.min.hz.list` остаётся
  закомментированным примером во всех трёх профилях).
* Пометки «не действует» на самих ключах не пересматриваем — их правильность
  обеспечивает тест-контракт (§4), а не наше разовое вычитывание.

## 4. Пункт 2: тест-контракт вместо ручной синхронизации

**Подход: не кодогенерация, а проверка.** Генератор кода потребовал бы новой зависимости
(python3 в `tests/run_tests.sh`, где сейчас только `cc`), шага сборки перед `assembleDebug`
и кодогенерации в дереве APK. Дешевле и надёжнее — оставить списки там, где они есть
(`SettingsFragment.java`), и завести host-тест, который **падает при любом расхождении**,
называя ключ.

`cfgkeys_note (key, path)` уже отдаёт ровно ту формулировку, которой пользуется GUI, и
различает: «действует» (`NULL`), «не действует на новом/старом пути», «ключ настройки
приложения», «устарел», «неизвестный ключ». Значит классификация выводится из таблицы
через публичный API — парсить C-исходник не нужно.

**Правила (тест `tests/test_inactive.c`):**

Пусть `K` — ключ настройки из `preferences.xml` (элементы, кроме групп `PreferenceScreen`),
приведённый к ini-виду заменой `_` → `.` (то же правило, что в `Config.load (SharedPreferences)`).

| `note(K, ATV14)` | `note(K, LEGACY)` | Класс | Требование |
|---|---|---|---|
| NULL | NULL | оба пути | нет ни в одном списке |
| NULL | ≠NULL | новый путь | есть в `kInactiveOnLegacy` |
| ≠NULL | NULL | старый путь | есть в `kInactiveOnAtv14` |
| ≠NULL | ≠NULL | ключ приложения | **нет** ни в одном списке |
| «неизвестный» | «неизвестный» | неизвестный | падение: строка GUI обязана быть в `cfgkeys.c` |

Плюс инварианты: `kInactiveOnAtv14` и `kInactiveOnLegacy` не пересекаются; каждый элемент
любого из списков — GUI-ключ соответствующего класса (лишний или не-GUI ключ = падение);
санитарные проверки самого парсера (найдено ≥ 30 GUI-ключей, ≥ 15 токенов в списках,
эталонные ключи классифицируются ожидаемо).

Следствие: `cs_select` из `kInactiveOnAtv14` уходит автоматически (тест это доказывает —
он падает на текущем коде), а строка README:122 правится руками (документ, не тест).

**Что тест не покрывает:** он проверяет согласованность с таблицей `cfgkeys.c`, а не
истинность самой таблицы (её проверяет `tests/test_cfgkeys.c` и живые проверки).

## 5. Пункт 1: `mode.min.hz.list` из GUI

### 5.1. Контракт ключа (проверено по коду)

| Свойство | Значение | Источник |
|---|---|---|
| Путь | `CFGKEY_BOTH` (Android 6-14) | `cfgkeys.c:31` |
| Формат | токены через пробел, `пакет=Гц` | `afrd.c:3148-3186` |

| Ёмкость | 8 записей; имя пакета ≤ 64 байт | `afrd.c:70-71` |
| Повтор пакета | берётся первая запись | `mode_min_hz_for`, `afrd.c:3191+` |
| Смысл порога | 6-9: отсев режимов ниже порога; 10-14: ровное кратное выше порога, иначе самый быстрый режим | README:108 |

### 5.2. Почему выборщик, а не текстовое поле

Значение — имена пакетов. Вводить `com.google.android.youtube.tv=50` с пульта нельзя —
ровно поэтому и появился экран выбора приложений (`docs/superpowers/specs/2026-10-06-afrd2-app-picker-design.md`, §1).
Спека выборщика уже зарезервировала для этого режим `pkg_value` (§4.3). Реализуем его:
число вводится с пульта (это цифры, а не латиница с точками), имя пакета — отметкой в списке.

### 5.3. UX режима `pkg_value`

* Список приложений — как сейчас: отметка, фильтр «Только плееры», уже выбранные пакеты
  видны всегда (в т.ч. удалённые).
* В строке справа от названия видно текущее значение: `50 Гц` (только в этом режиме).
* Клик по строке открывает диалог с одним полем — число (дробное допускается: `59.94`,
  `23.976`). Кнопки: **Отмена** (ничего не меняем), **Снять отметку** (только если строка
  отмечена; значение строки убирается), **Сохранить**. Неверное число (не число, NaN,
  вне 1…1000) — сообщение, диалог не закрывается.
* Сохранение в неотмеченной строке = отметка + значение. Если отмечено уже 8 записей —
  отказ с сообщением (иначе девятая запись молча отбрасывается демоном).
* «ГОТОВО»/Back собирают значение как `пакет=Гц` через пробел, в порядке отметки, и
  возвращают хосту — как в существующих режимах (`multi`/`single`).
* Записи, которые демон игнорирует (`пакет` без `=`, пустое значение, неразборчивое или
  вне диапазона число), при разборе отбрасываются — ровно так же, как их видит демон.
  Запись вида `пакет` без `=`, наоборот, сохраняется при записи как есть: GUI не должен
  молча удалять пользовательский текст, даже если демон его игнорирует.

### 5.4. Компоненты

| Компонент | Тип | Ответственность |
|---|---|---|
| `ru.cobra.zap.afrd.PkgValues` | новый класс, **без Android-зависимостей** | разбор/сборка значения «пакет=число» (порядок, повторы, отброшенные записи) |
| `tests/PkgValuesTest.java` | host-тест на JVM | проверки разбора/сборки, включая краевые (дубликат, `пакет` без `=`, мусор, границы 1 и 1000) |
| `AppsPickerActivity` | существующая Activity | режим `pkg_value`: показ значения, диалог числа, лимит 8, сборка результата |
| `SettingsFragment` | существующий фрагмент | строка настройки в `kAppsPrefs`; summary с числами |
| `Config.itemType`, `MainActivity.seedOptions` | существующие | тип ключа (`TYPE_STR`) и посев значения из профиля в `ini_options` |
| `res/xml/preferences.xml`, строки ru/en | ресурсы | сама строка настройки и тексты |

Чистая логика формата живёт в отдельном классе без Android-типов именно ради host-теста:
`run_tests.sh` компилирует его тем же `javac`, которым собирается APK, и запускает на JVM.

### 5.5. Поток данных (не меняется)

```
SettingsFragment → XAppsPreference (строка) → AppsPickerActivity (pkg_value)
        ↑                                              │ RESULT_VALUE = "пакет=Гц пакет=Гц"
        └── setApps(value) → mMain.applyPrefs() ───────┘
                 (ini + Control.reload() → демон перечитывает конфиг)
```

## 7. Открытые вопросы к владельцу

1. Переводить ли `fps.correct.list` («пакет=проценты») на тот же экран выбора — сейчас
   остаётся текстовым полем, то есть два способа задать «пакет=число». Формат и разбор
   уже общие (`PkgValues`), нужен лишь режим с другой единицей измерения и диапазоном.
2. Нужна ли строка для `mode.min.hz.list` вообще: альтернатива — оставить ключ
   «экспертным» (правится в профиле/по ssh) и вместо GUI научить приложение не затирать
   ручные правки профиля при обновлении APK (сейчас затирает).
