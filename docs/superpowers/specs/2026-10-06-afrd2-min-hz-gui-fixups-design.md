# AFRd2: доводка строки `mode.min.hz.list` — контракт настроек, посев, обрезка, длина имени пакета

Дата: 2026-10-06. Статус: спека на ревью владельцу.
Ветка работы: `afrd2-gui-fixups` (от `master` = `62eb412`).

Дополняет спеку `docs/superpowers/specs/2026-10-06-afrd2-inactive-keys-drift-and-min-hz-gui-design.md`
(в ней — сам экран выбора приложений и тест-контракт пометок GUI; здесь — доводка по итогам
ревью и разговора с владельцем).

## 1. Что делаем

Четыре пункта, все — из уже выявленных расхождений «GUI обещает — демон делает не то»:

1. **Две инертные строки.** `fps.measure.envelope.early.ms` и `fps.cadence.fix.ms` есть в GUI и в
   `cfgkeys.c` (`CFGKEY_ATV14`), но отсутствуют в `Config.itemType`. Из-за этого `Config.load
   (SharedPreferences)` их не переносит, и правка полей не доходит до `afrd.ini`: в профиле
   `fps.measure.envelope.early.ms=14000`, а строка показывает умолчание из `preferences.xml` —
   12000. Демон читает профильные значения.
2. **Нет теста на это расхождение.** Пункт 2 прошлой задачи закрывает дрейф пометок, но набор
   `Config.itemType` не проверял никто — потому дефект и жил.
3. **Правило посева живёт только в комментарии.** Исправление Important-находки ревью
   («пустое значение профиля не сеем») проверено лишь живьём; постоянного теста нет.
4. **Лимит демона и длина имени пакета — молчаливые.** Значение из более чем восьми записей
   проходило через GUI без предупреждения (демон берёт первые восемь), а имя пакета длиннее
   63 байт демон обрезает (проверено: `MODE_MIN_HZ_PKG_LEN 64`, журнал «…verylon: 50.00 Гц или выше»
   для 107-символьного пакета), после чего порог для такого плеера не работает — сравнение идёт
   с полным именем пакета переднего плана.

## 2. Факты, собранные для пункта 4 (проверено на стенде `.50`, ATV14)

| Что | Факт |
|---|---|
| Пакет с именем 107 символов | ставится, виден системе, точка входа резолвится |
| Пакет с именем 171 символа | ставится |
| Пакет с именем 321 символ | отказ установки: `INSTALL_PARSE_FAILED_BAD_PACKAGE_NAME: Invalid manifest package: Invalid filename` |
| Максимум на стендах владельца | `.50` — 59 символов (`com.android.providers.settings.auto_generated_rro_product__`), `.76` — 53 (`com.google.android.leanbacklauncher.partnercustomizer`) |
| Наш буфер | 63 полезных байта: `afrd.c` (`MODE_MIN_HZ_PKG_LEN 64`, `g_cur_pkg`, `video_pkg`) и `fps_class.c` (`pkg [64]` дважды) |
| Кого это задевает | `mode.min.hz.list`, `fps.correct.list`, `fps.correct.av1.pkg` и определение пакета переднего плана (`g_cur_pkg` — то же, что нужно `switch.skip.pkg`; сам `strlist` для `switch.skip.pkg` динамический, там лимита нет) |

Вывод: 63 байта — ограничение не Android, а наше; реальные имена на ATV-приставках короче, но
имена до ~200 символов система принимает, и тогда наш порог/исключение для такого плеера молча
не срабатывают.

## 3. Решения владельца (2026-10-06)

* Пункты 1–3 — делать (в этой работе).
* Пункт 4 в части восьми записей — «обрезать при сохранении с предупреждением».
* Пункт про длину имён пакетов — вопрос владельца «а такие пакеты бывают?»; ответ дан выше (§2),
  решение — поднять буфер демона и предупредить в GUI, если имя всё же длиннее (см. §4.4).
* `fps.correct.list` на выборщик **не** переводим (пока).
* Проверка на ATV9: зажимает ли YouTube частоту кадров — отдельное исследование (§5).

## 4. Что делаем по пунктам

### 4.1. Инертные строки (пункт 1)

* `Config.itemType.put ("fps.measure.envelope.early.ms", TYPE_INT)` и
  `put ("fps.cadence.fix.ms", TYPE_INT)`.
* Оба ключа добавляются в `MainActivity.seedOptions()`, чтобы при первой установке строка
  показывала значение из профиля, а не умолчание GUI.
* Умолчания в `preferences.xml` приводятся к профильным (`14000` для
  `fps_measure_envelope_early_ms`), чтобы первый же сеанс настроек не переписал профиль на 12000.

### 4.2. Тест-контракт набора ключей (пункт 2)

`tests/test_inactive.c` дополняется проверкой: каждая строка GUI, кроме ключа настройки приложения
(`toast_hz`), обязана присутствовать в `Config.itemType`. Разбор — тот же текстовый, что уже есть
для `cfgkeys.c`; отдельный файл не заводим (тест и так про согласованность трёх источников: таблицы
ключей, XML и Java-кода).

### 4.3. Правило посева — в отдельный класс (пункт 3)

Новый класс `ru.cobra.zap.afrd.Seed` без Android-зависимостей:

```java
public static String value (String profileValue)   // null/пусто → null (не сеять), иначе значение
public static boolean shouldSeed (String profileValue, boolean alreadyInPrefs)
```

Host-тест `tests/SeedTest.java` (через `tests/run_tests.sh`) фиксирует: пустое значение не сеется,
непустое сеется, уже имеющаяся настройка не перетирается. `MainActivity.seedOptions()` переходит на
этот класс — правило перестаёт быть только комментарием.

### 4.4. Восемь записей и длина имени пакета (пункт 4)

* `PkgValues.MAX_ENTRIES = 8` уже есть; добавляется `PkgValues.trim (Map, int)` — обрезка до лимита
  с сохранением порядка; в `AppsPickerActivity` при сохранении избыток отбрасывается **с сообщением**
  (сколько записей не влезло), а не молча.
* Демон: общий `#define PKG_NAME_LEN 256` в `afrd.h`; применяется в `afrd.c`
  (`MODE_MIN_HZ_PKG_LEN`, `g_cur_pkg`, `video_pkg`) и `fps_class.c` (оба `pkg [64]`). 256 покрывает
  всё, что система принимает (321 отвергается самой установкой).
* GUI: `PkgValues.MAX_PKG_LEN = 255`, и если имя пакета длиннее, строка помечается как непригодная
  и не добавляется в значение — с сообщением, почему. (После правки демона это практически
  недостижимо, но молчать нельзя.)
* Тесты: `PkgValuesTest` (обрезка, `MAX_PKG_LEN` сверяется с `PKG_NAME_LEN` из `afrd.h` — тем же
  приёмом, что и таблица ключей), `test_pkgdet` — кейс с длинным именем пакета в дампе
  (сейчас такого кейса нет).

## 5. Исследование на ATV9: зажимает ли YouTube частоту кадров

Вопрос владельца: нужен ли `mode.min.hz.list` для YouTube на старом пути (на ATV14 «зажим» YouTube
был причиной появления ключа, README ограничение 8).

Методика (наблюдение, без правок кода): на `.76` с нашим APK поднять наш демон, запустить YouTube,
дать демону переключить режим под ролик, затем сравнить частоту подачи кадров с частотой ролика:
замер `vdec_status`/журнал демона до и после переключения. Признак «зажима» — подача остаётся на
частоте исходного режима (вдвое реже периода дисплея), а не на своей. Контроль — тот же ролик в VLC
(он не зажимает). Владельцу в отчёт: работает ли порог и нужен ли он на 6–9.
