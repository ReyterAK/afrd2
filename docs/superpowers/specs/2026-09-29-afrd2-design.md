## 1. Цель и критерии приёмки

Сделать AFR (авто-подстройку частоты обновления HDMI под частоту кадров видео) работающим на
Android TV 14 / Amlogic S905X5M **для любых приложений**, включая те, у которых нет собственного AFR.

Целевое устройство: X88 Pro X5M (slimboxtv, ATV14, ядро 5.15.153, **32-бит** userspace, root через
Magisk 24.3, SELinux permissive).
Порт-цель по коду: Amlogic S905X5M (s5/`s7d`), но дизайн не должен быть привязан к модели.

Критерии приёмки (проверяются на стенде):

1. Видео 23.976 / 24 / 25 / 29.97 / 30 / 50 / 59.94 / 60 fps → HDMI переключается в подходящий
   режим **за ≤2 с** после старта воспроизведения; фактический режим (по `disp_mode`) и состояние
   SurfaceFlinger (`activeMode`) совпадают.
2. При остановке/выходе из плеера режим возвращается к исходному (поведение настраиваемое).
3. Приложения со своим AFR (Plex, OTT Navigator, GTBox, Kodi) **не ломаются**: если режим уже
   соответствует контенту — демон не вмешивается.
4. После штатного завершения или `SIGTERM`/`SIGINT` система сразу возвращается в штатное состояние
   (флаг backdoor снят, режим не «залип»). После `SIGKILL` — состояние восстанавливается при
   следующем старте демона (стартовая проверка «залипшего» флага); опционально — сторожевой режим
   `--guard <pid>`, снимающий флаг немедленно.
5. Демон стартует автоматически после перезагрузки и не требует ручных действий.
6. Демон **никогда** не читает debug-узлы `dump_vdec_chunks` / `dump_vdec_blocks` / `dump_path_monitor`
   (риск kernel panic, см. журнал §4).

## 2. Проверенные факты, на которых стоит дизайн

(подробности и протоколы — в журнале `afrd2-journal.md`, разделы 3–5)

| Что | Состояние на ATV14 / 5.15 | Решение в порте |
|---|---|---|
| uevent'ы декодера (`amvdec_*`, `SUBSYSTEM=platform`) | **нет** (V4L2-декодеры) | поллинг `/sys/class/vdec/vdec_status` |
| `vdec_status`: `frame rate` / `frame dur` | **недостоверны** (25→50, 50→100, 23.976→30) | не использовать |
| `vdec_status`: `frame count`, `device name` | работают | основа детекта видео и измерения fps (Δ/Δt) |
| `/sys/class/display/mode` (запись) | **режим не переключает** | не использовать |
| `/sys/class/display/fr_hint`, `fr_policy`, `video_framerate_adapter` | инертны | не использовать |
| `/vendor/bin/meson_display_client -F` | `ret:1`, без эффекта | не использовать |
| `/vendor/bin/meson_display_client -c WxH@R` | HDMI переключает, SF рассинхронизируется | не использовать |
| `ISurfaceComposer::setOverrideFrameRate` (AIDL, код 55) | вызов проходит как root, режим **не** меняет (нет VRR) | не использовать |
| SF content detection (`ro.surface_flinger.use_content_detection_for_refresh_rate`) | включается, но без данных от приложения бесполезна | не использовать |
| **SF backdoor: транзакция 1035** (`setActiveModeFromBackdoor`) | **работает** как root, режим меняется, SF синхронен, флаг `debugDisplayModeSetByBackdoor=true` | **основной приёмник** |
| `/sys/class/amhdmitx/amhdmitx0/{disp_cap,attr,dc_cap,frac_rate_policy,edid}` | работают | использовать (список режимов, цвета, дробные частоты) |
| `hdmi.state` (`/sys/class/switch/hdmi/*`) | **нет** | `/sys/class/extcon/extcon0/state` («HDMI=1») или `amhdmitx0/hpd_state` |
| `DEFAULT_HDCP_AUTHENTICATED` (`/sys/module/hdmitx20/...`) | **нет** | HDCP-ветку сделать необязательной |

Факт-лист кода транзакции (проверено вживую):

```
service call SurfaceFlinger 1035 i32 <modeId>          # установить режим (root)
service call SurfaceFlinger 1035 i32 <несущ. modeId>   # вернуть BAD_VALUE и СНЯТЬ флаг backdoor
```

Парцель: `i32 modeId` [+ опционально `i64 displayId`, `f minFps`, `f maxFps`]; интерфейсный токен не
нужен; сервис — `SurfaceFlinger` (легаси-объект). `modeId` берётся из списка режимов SF и **меняется**
после рестарта SurfaceFlinger (наблюдалось 45..56 → 0..13), поэтому резолвится динамически.

## 3. Архитектура

Один демон (c, bionic, armeabi-v7a), запуск под root. Никаких HAL/патчей прошивки.

```
   ┌────────────── afrd2 (root) ──────────────┐
   │ 1 trigger    poll /sys/class/vdec/vdec_status │
   │ 2 fps        Δframe_count/Δt → класс частоты   │
   │ 3 resolver   список режимов SF (id↔Hz)         │
   │ 4 sink       binder: SF 1035 (modeId)          │
   │ 5 guard      restore + сброс флага backdoor    │
   │ 6 api        UDP 50505 (совместим с upstream)  │
   │ 7 state      shmem-файл статуса                │
   └───────────────────────────────────────────────┘
         файл конфига: <кэш приложения>/afrd.ini  (вариант B, §8.1)
```

### 3.1 Компоненты и интерфейсы

* **trigger** (вход: `/sys/class/vdec/vdec_status`; выход: событие `video_started`/`video_stopped`).
  Опрос 300 мс (настраиваемо, 100–2000). Признак «видео идёт» — `device name: <...>` и
  `frame count` растёт; `No vdec.` — стоп. Дебаунс старта/стопа (настраиваемо), чтобы перемотка и
  смена серии не давали лишних переключений.
* **fps** (вход: выборки `frame count` с интервалом 0.5 с; выход: частота класса
  {23.976, 24, 25, 29.97, 30, 50, 59.94, 60}). Решение принимается по доверительному
  интервалу: счётчик дискретен (±1 кадр), метки времени — середины чтений с ±(полусумма
  длительностей крайних чтений). Пока интервал не укладывается в одну *группу* режимов
  (23.976/24, 29.97/30, 59.94/60 — на HDMI это один режим), окно расширяется шагом
  `window.ms/3` до `window.max.ms`. Приоритетный источник — подсказка от плеера через API
  (см. 3.3), если она пришла.
* **resolver** (вход: вывод `dumpsys SurfaceFlinger`, строки `{id=…, hwcId=…, resolution=…,
  refreshRate=…}`; выход: `modeId` для частоты и разрешения). Кэш + инвалидация при смене PID
  SurfaceFlinger. Первая версия парсит `dumpsys` (просто, проверяемо); переход на AIDL
  (`getPhysicalDisplayIds` → `getPhysicalDisplayToken` → `getDynamicDisplayInfoFromToken`) — только
  если парсинг окажется хрупким.
* **sink** (вход: `modeId`; выход: успех/ошибка + фактический режим). Способ по умолчанию —
  запуск системного `/system/bin/service call SurfaceFlinger 1035 i32 <modeId>` (демон работает под
  root, поэтому вызов проходит проверку `uid==0`; способ проверен вживую). Оптимизация на будущее —
  прямая отсылка той же транзакции через `/dev/binder` (без линковки с `libgui`/`libbinder`),
  если накладные расходы на `fork/exec` окажутся значимыми.
* **guard** — единственное место, которое помнит состояние: исходный `modeId`, поднят ли флаг
  backdoor. Снимает флаг при: остановке видео, `SIGTERM`/`SIGINT`, старте демона (наследие падения),
  истечении страховочного таймаута (если видео «потерялось»).
* **api** — UDP 127.0.0.1:50505, совместим с upstream: `frame_rate_hint <fr>`, `refresh_rate <rr>`,
  `color_space ...`, `status`, `reconf`. Позволяет плеерам сообщать точную частоту (снимает
  погрешность измерения).
* **state** — shmem-файл (как upstream) для GUI/статуса.

### 3.2 Поведение (сценарии)

1. **Старт видео**: trigger → fps (или подсказка) → resolver → sink(1035, правильный режим).
   Если текущий режим уже подходит — sink не вызывается.
2. **Стоп видео**: guard → sink(1035, исходный режим) → сброс флага backdoor (1035 с несуществующим id).
3. **Пауза**: настраиваемо: `pause.keep=1` (по умолчанию) — режим не трогаем; `pause.keep=0` —
   вернуть исходный.
4. **Смена серии/файла с той же частотой**: не переключать (сравнение с текущим режимом).
5. **Конфликт с приложением со своим AFR**: если перед нашим вмешательством режим уже равен
   целевому — не трогаем. Если приложение запросит иной режим во время нашего удержания — фреймворк
   его проигнорирует (флаг backdoor); поэтому удержание минимально и снимается на стопе.
6. **Аварийные ситуации**: SF недоступен → пассивный режим + лог; резолв не нашёл режим → не
   переключаем и пишем предупреждение; ядро вернуло ошибку чтения sysfs → ретрай с backoff.

### 3.3 Конфиг (afrd.ini), совместимость

Сохраняем стиль upstream (`key=value`, `#` комментарии), ключи:

```
enable=1
trigger.poll.ms=300
trigger.start.debounce.ms=500
trigger.stop.debounce.ms=1500
fps.measure.window.ms=1500
fps.measure.window.max.ms=6000
fps.prefer.api=1
fps.blacklist.rates=            ; например 29.97 30
mode.prefer.exact=0
mode.use.fract=0
switch.delay.on=250
switch.delay.off=3000
switch.restore.on.stop=1
pause.keep=1
cs.select=2160p[4-9].*=420 .*=444
cs.list.path=/sys/class/amhdmitx/amhdmitx0/dc_cap
cs.path=/sys/class/amhdmitx/amhdmitx0/attr
hdmi.state=/sys/class/extcon/extcon0/state
vdec.sysfs=/sys/class/vdec
log.file=/data/local/afrd.log
log.enable=1
```

Ключи upstream, потерявшие смысл (`uevent.*`, `mode.path`, `vdec.sysfs` для dump-узлов, `switch.hdmi`
в старом виде), либо удаляются, либо помечаются как игнорируемые с предупреждением в логе.

## 4. Стратегия изменений: аддитивный форк (сохраняем поддержку Android 6–9)

Порт делается **форком** upstream (репозиторий `/home/reyter/AI/afrd2`), а не новым проектом.
Переиспользуется: парсер конфига, CLI/main-цикл, shmem, API UDP 50505, логирование, алгоритм выбора
режима (`display_mode_*`, `mode.prefer.exact`, `mode.use.fract`, blacklist), colorspace (`attr`,
`dc_cap`), `frac_rate_policy`, структура «демон + конфиг + приложение».

Заменяются три подсистемы (их старые реализации физически не работают на ядрах 5.15) **аддитивно**:
на старом окружении используется прежний путь, на новом — добавленный, выбор по детекту на старте
(наличие `vdec_status`, отсутствие `amvdec_*`-uevent'ов, наличие backdoor SurfaceFlinger).

| Слой | Android 6–9 (ядро 3.14/4.9), как было | Android 10–14 (ядро 5.15), добавляется |
|---|---|---|
| триггер | netlink uevent'ы `amvdec_*`/`tv` | поллинг `/sys/class/vdec/vdec_status` |
| источник fps | `vdec_status.frame_rate/frame_dur`, `dump_vdec_*` | измерение Δ`frame count`/Δt (+ API-подсказка) |
| приёмник режима | запись `/sys/class/display/mode` | backdoor SurfaceFlinger, транзакция 1035 |
| признак HDMI | `/sys/class/switch/hdmi/*` | `/sys/class/extcon/extcon0/state`, `amhdmitx0/hpd_state` |
| HDCP | путь `/sys/module/hdmitx20/...` | путь отсутствует → ветка необязательна |

Ниже (§4.1) перечислены конкретные удаления/добавления, которые нужны и в аддитивном варианте:
код, читающий `dump_vdec_*`, должен быть **недоступен** на новых ядрах (риск паники), а доверие к
`frame rate`/`frame dur` — отключаться по детекту/настройке.

### 4.1 Конкретика

Удаляется/отключается на новых ядрах:
* `query_vdec_chunks()`, `query_vdec_blocks()` (изменённый формат + риск kernel panic при teardown);
* доверие к `frame rate` / `frame dur` из `vdec_status`;
* запись в `mode.path` (`/sys/class/display/mode`) и `display_mode_null()` как способ «чёрного кадра»;
* жёсткая привязка к `/sys/class/switch/hdmi/*` и `/sys/module/hdmitx20/...`;
* обработка uevent'ов (остаётся только в ветке старых ядер).

Добавляется:
* поллинг-триггер + измерение fps по `frame count`;
* резолвер режимов (id ↔ Hz) с кэшем;
* клиент транзакции 1035 (+ сброс флага backdoor);
* guard-логика (возврат режима, снятие «залипшего» флага при старте/выходе);
* новый профиль конфига для ATV14 (§3.3).

Сохраняется без изменений: см. список в первом абзаце §4.

Открытый вопрос по «чёрному кадру»: на ATV14 нет дешёвого способа погасить экран на время
переключения (запись `null` в `mode.path` не работает). Варианты: (а) не гасить вовсе (переключение
backdoor-ом занимает ~0.3–1 с, экран моргает как при обычной смене режима); (б) гасить через
`setDesiredDisplayModeSpecs`/`sf.early...` — не проверено; (в) артефакт `AMovie`/overlay — избыточно.
Предложение: начать без гашения (вариант «а»), при жалобе на «щелчок» экрана вернуться.

## 5. Упаковка и установка (только после согласования!)

Принят вариант **B — как в оригинальном AFRd**: обычный APK, запуск демона из приложения, автозапуск
после перезагрузки. Magisk-модуль — опциональный бонус на будущее, не основной путь.

* **APK** (позже, отдельным этапом) содержит бинарник демона в `res/raw/afrd_armeabi_v7a`,
  извлекает его в свой кэш, делает исполняемым и запускает через `su`
  (`<cache>/afrd -k -D <cache>/afrd.ini`); `BootCompleteReceiver` по `BOOT_COMPLETED` поднимает
  демон после перезагрузки; статус/остановка — через API (UDP 50505) и pid-файл.
* Правки в приложении относительно upstream: поднять тулчейн (AGP/Gradle/Java), добавить профиль
  конфига для ATV14 и ветку в `Control.extractConfig()` (сейчас он отказывает на ядре 5.x),
  привести foreground-service к требованиям Android 14 (`foregroundServiceType` либо отказ от
  постоянного FGS), при желании заменить `libsuperuser` собственным `su`-враппером.
* Сборка демона: NDK, `APP_ABI=armeabi-v7a` (userspace 32-бит), `APP_PLATFORM=android-21`.
* Известные минусы варианта B (осознанно принимаем): демон живёт, пока приложение установлено и не
  «остановлено»; удаление/очистка данных приложения = AFR пропадает; автостарт может не сработать,
  если систему/приложение выгрузят (лечится исключением из оптимизации батареи).
* Любая установка в ОС — **после отдельного согласования** (правило владельца).

Предлагаемый набор (выполняется на стенде 192.168.88.50, тестовые клипы уже лежат в
`/sdcard/Download/afr/`: 23.976, 24, 25, 50, 60 — по 12 с и по 60 с):

1. **Матрица частот**: VLC (без встроенного AFR) × {23.976, 24, 25, 50, 60} → ожидаемые режимы
   {1080p24(23.976), 1080p24, **1080p25**, 1080p50, 1080p60}. Для 25 fps ожидание исправлено по
   живому прогону 2026-09-29: резолвер ATV14 берёт точную частоту из таблицы SurfaceFlinger, а не
   удвоение. Фиксируем: `mode`, `disp_mode.h/v_freq`, SF `activeMode`, время до переключения.
2. **Возврат**: останов → исходный 1080p60 (или пользовательский), флаг `backdoor=false`.
3. **Совместимость**: GTBox (свой AFR) → переключает как раньше; Plex/OTT Navigator — то же.
4. **Устойчивость**: `kill -9` демона во время видео → флаг остаётся поднятым (ожидаемо для
   `SIGKILL`), при следующем запуске демона снимается автоматически (проверяем); `SIGTERM` → снят
   немедленно. Перезагрузка бокса → демон поднялся, режим штатный.
5. **Не-регресс**: убедиться, что демон не открывает `dump_vdec_*` (проверка по strace/логу и по
   отсутствию паник).
6. **API**: `nc -u 127.0.0.1 50505` → `frame_rate_hint 23976`, `status`.

Тесты оформляются как скрипты стенда (`tools/stand/*.sh`) с логированием результата в журнал.

## 7. Риски и меры

| Риск | Мера |
|---|---|
| Демон оставил флаг backdoor → приложения со своим AFR перестают переключать режим | снятие флага на стопе/SIGTERM/старте; проверка «залипшего» флага при запуске; лог |
| `modeId` меняются после рестарта SurfaceFlinger | резолв при каждом старте видео + инвалидация по PID SF |
| Backdoor-коды есть в AOSP 14, могут исчезнуть в A15/A16 | детект при старте (пробный вызов 1035 с текущим режимом); явная ошибка + fallback (сообщить) |
| Неточность измерения fps по счётчику кадров (один кадр за 1.5 с = 2.8% — больше зазора 24/25 в 2.15%) | решение по доверительному интервалу ±1 кадр и ±неопределённость меток времени; расширение окна до 6 с, пока интервал не уложится в одну группу режимов; приоритет API-подсказки |
| Паника ядра при обращении к debug-узлам vdec | запрет на эти узлы в коде (unit-тест/ревью), логирование только разрешённых чтений |
| Конфликт с системным `match_content_frame_rate`/приложениями | не вмешиваться, если режим уже подходит; держать флаг минимально |
| HDCP/цветовые пространства на 5.15 | HDCP-ветка необязательна; colorspace применять как upstream |

## 8. Решённые вопросы (ответы владельца, 2026-09-29)

1. **GUI**: в первой версии — только конфиг + API (UDP 50505) + статистика в shmem;
   приложение (APK) — отдельным этапом.
2. **Пауза**: режим на паузе **не** возвращаем (`pause.keep=1` по умолчанию).
3. **Чёрный кадр**: затемнения при переключении **нет** в v1 (на ATV14 дешёвого способа погасить
   экран нет; переключение занимает <1 с).
4. **Preferred mode**: если в настройках Android TV задан «предпочтительный режим» — использовать его
   как исходный для возврата; иначе — фактический режим на момент старта демона.
5. **Способ установки/автозапуска демона**: выбран **вариант B — как в оригинальном AFRd**: обычный
   APK, запуск демона из настроек приложения (`su`), автозапуск после перезагрузки
   (`BootCompleteReceiver`). Magisk-модуль — опциональный бонус на будущее. Детали — §5.

### 8.1 Компромиссы варианта B (приняты осознанно)

* демон живёт, пока приложение установлено и не «остановлено» пользователем;
* удаление/очистка данных приложения → AFR пропадает (лечится повторным включением в приложении);
* если система выгрузит приложение агрессивно, автостарт после ребута может не сработать
  (рекомендуется исключить приложение из оптимизации батареи);
* зато UX ровно как в оригинале и не требуется установка модуля в систему.

## 9. Что НЕ входит в объём

* Правка вендорского HWC/SurfaceFlinger/прошивки.
* Работа на не-AmLogic устройствах и на Android < 14 (upstream-ветки сохраняются в истории).
* Патч самого приложения AFRd (решается отдельно, см. §8 п.1).
