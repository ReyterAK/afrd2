# AFRd2: экран выбора приложений (чёрный список плееров и другие пакетные настройки)

Дата: 2026-10-06. Статус: спека на ревью владельцу.
Ветка работы: `afrd2-app-picker` (от `master` = `707e90b`).

## 1. Цель

Дать пользователю Android TV возможность задавать настройки, значения которых — **имена
пакетов приложений**, без ручного ввода этих имён с пульта.

Первое применение — `switch.skip.pkg` («плееры, которым AFR мешает»): сейчас ключ есть в
профиле, но его нет ни в GUI, ни в `Config.itemType`, поэтому рекомендация ЧАВО
«добавьте плеер в чёрный список» невыполнима для пользователя.

Решения владельца (2026-10-06):

1. **Вариант A**: полноэкранный список установленных приложений с отметками, а не текстовое
   поле и не диалог.
2. **Фильтр по умолчанию**: только приложения, умеющие открывать видео.
3. Выборщик делается **общим** (переиспользуемым) — первым вторым потребителем становится
   `fps.correct.av1.pkg`.

### Критерии успеха

* В настройках появляется строка, значения которой задаются выбором приложений из списка;
  ввод имени пакета с пульта не требуется ни в одном сценарии.
* `switch.skip.pkg` редактируется из GUI, значение доезжает до демона без перезапуска
  приложения (демон перечитывает конфиг), проверено живьём.
* `fps.correct.av1.pkg` использует тот же механизм в режиме одиночного выбора (доказательство
  переиспользуемости, а не декларация).
* Существующий путь «настройка → ini → демон» не меняется: ни новый формат хранения, ни
  новый способ уведомления демона не вводятся.

## 2. Не-цели

* `mode.min.hz.list` и `fps.correct.list` («пакет=число») на выборщик **не** переводятся:
  им нужен ввод числа, это отдельная задача. (`fps.correct.list` остаётся в GUI текстовым
  полем, как сейчас; `mode.min.hz.list` в GUI отсутствует — не добавляем.) Выборщик
  проектируется так, чтобы их можно было добавить (см. §4.3, режим `PKG_VALUE`), но код
  этого режима в этой задаче не пишется.
* Изменение демона, формата конфига, API (UDP 50505).
* Правка legacy-пути демона (Android 6–9): ключ `switch.skip.pkg` — ATV14-ключ и живёт в
  группе «Настройки для Android 10 и выше». Единственное изменение в приложении на legacy —
  пометка «не действует» (§4.5); поведение демона там не меняется.

## 3. Ограничения (проверено в коде)

| # | Факт | Следствие для дизайна |
|---|---|---|
| 1 | `addFragment(..., toplevel=true)` в `MainActivity` вычищает back stack (`popBackStack` до entry 0) | экран выбора **нельзя** вставлять в `content_holder` как обычный фрагмент: он уничтожит экран настроек под собой |
| 2 | Back-обработка в приложении — внутреннее дело фрагмента (`FragmentBack`); `activeFrag` в `MainActivity` обновляется только в `addFragment` | фрагмент с собственной навигацией потребовал бы правки навигации `MainActivity` и слушателя `OnBackStackChanged` |
| 3 | В приложении уже есть вспомогательная Activity (`ActionActivity`, без UI) | отдельная Activity под модальный экран — существующий приём, а не новая сущность |
| 4 | `applyPrefs()` (запись ini + `Control.reload()`) живёт в `MainActivity` | экран выбора не должен дублировать эту логику — он только **выбирает**, применяет вызывающий (см. §4.2) |
| 5 | `android.preference` (не AndroidX), `compileSdk 27`, no `RecyclerView` | список — `ListView` + `BaseAdapter` |
| 6 | `minSdk 23`, `targetSdk 28` | ограничения видимости пакетов Android 11 не действуют; при будущем подъёме `targetSdk` ≥ 30 список молча урежется (нужен `<queries>`/`QUERY_ALL_PACKAGES`) — записать комментарием в коде |
| 7 | Демон читает список по пробелам (`spaces = " \t\r\n"`) | храним и пишем значения как строку пакетов через **пробел**; никаких запятых |
| 8 | `fps.correct.av1.pkg` — один пакет (`strcspn(package, " \t")`) | режим `SINGLE` пишет один пакет; лишние — отбрасываются на стороне демона, но GUI их и не даст выбрать |

## 4. Архитектура

### 4.1. Компоненты

| Компонент | Тип | Ответственность |
|---|---|---|
| `ru.cobra.zap.xprefs.XAppsPreference` | класс настройки (наследник `Preference`) | строка в списке настроек: заголовок, автоматический summary из текущего значения, по клику — открытие экрана выбора (через интерфейс-слушатель, задаваемый хост-фрагментом) |
| `ru.cobra.zap.afrd.gui.AppsPickerActivity` | Activity (модальная, `exported=false`) | полноэкранный выбор приложений; получает на вход ключ/режим/текущее значение, возвращает новое значение результатом |
| `AppPickerAdapter` (вложенный в Activity или отдельный файл) | `BaseAdapter` | строки списка: иконка, название, имя пакета мелким шрифтом, отметка выбора; ленивое кэширование иконок |
| `res/layout/activity_apps_picker.xml` | layout | шапка (заголовок + кнопка «Готово» + переключатель фильтра) и `ListView` |
| `res/layout/item_app.xml` | layout строки | иконка 48dp, два текста, индикатор отметки |

`XAppsPreference` не содержит логики выбора: она лишь сообщает хосту «пользователь нажал» —
так одна и та же строка работает и в общей группе настроек, и в подэкранах.

### 4.2. Поток данных

```
SettingsFragment                     AppsPickerActivity                 демон
      |                                       |                           |
 click по XAppsPreference                     |                           |
      |-- startActivityForResult(intent) ---->|                           |
      |   extras: ini_key, mode, value        |  AsyncTask:               |
      |                                       |  PackageManager → список  |
      |                                       |  фильтр/отметки/скролл    |
      |<-- setResult(RESULT_OK, newValue) ----|                           |
      |                                       |                           |
 запись в SharedPreferences "ini_options"     |                           |
      |-- mMain.applyPrefs(): load ini → override → save ini → reload() ->| правка mtime
      |                                       |                    reconf → перечитать
```

Ключевая деталь: экран выбора **не пишет** конфиг и не трогает демон. Это сохраняет
единственную точку применения настроек (`MainActivity.applyPrefs()`) и делает экран
переиспользуемым из любого места, включая будущие пункты.

Значение передаётся и возвращается **как есть**, в том же виде, в котором лежит в ini
(строка пакетов через пробел), без переупаковки.

### 4.3. Интерфейс (extras/result)

| Ключ | Значения | Назначение |
|---|---|---|
| `key` | строка ключа настройки в форме prefs (`switch_skip_pkg`) | какую настройку редактируем (для однозначности, заголовков и журнала приложения) |
| `title` | строка | заголовок экрана (хост передаёт локализованный текст); если пусто — берётся заголовок настройки |
| `mode` | `multi` / `single` | `multi` — список пакетов через пробел; `single` — один пакет или пусто |
| `value` | текущее значение в формате ini | предзаполнение |
| `filter` | `video` / `all` | стартовое состояние фильтра (по умолчанию `video`) |
| результат `value` | строка | новое значение в формате ini |

Зарезервировано на будущее (в этой задаче не реализуется): режим `pkg_value` — список
`пакет=число` для `mode.min.hz.list` / `fps.correct.list`.

Соответствие «ключ → режим» задаётся хостом (`SettingsFragment`) явной картой, а не эвристикой:

| Ключ настройки | Режим |
|---|---|
| `switch_skip_pkg` | `multi` |
| `fps_correct_av1_pkg` | `single` |

### 4.4. Список приложений

Загрузка — в `AsyncTask` (на ATV это десятки–сотни пакетов; в главном потоке нельзя).

**Фильтр «только плееры» (по умолчанию).** В список попадают пакеты, полученные объединением
результатов `PackageManager.queryIntentActivities()` по набору интентов «открыть видео»:
`ACTION_VIEW` с типом `video/*` **и** с конкретными распространёнными типами
(`video/mp4`, `video/x-matroska`, `video/webm`, `video/x-msvideo`, `video/mpeg`,
`video/quicktime`, `video/mp2t`, `video/x-flv`, `video/3gpp`, `application/x-mpegURL`,
`application/vnd.apple.mpegurl`).

Почему недостаточно одного `video/*`: сопоставление идёт по фильтрам приложения — интент с
типом `video/*` не совпадает с фильтром, объявившим `video/mp4` (совпадение проверяется как
«точный тип / major `*` / `*/*` в фильтре»). Объединение покрывает оба способа объявления.

**Обязательные включения поверх фильтра:**

* пакеты, уже выбранные в настройке (даже если приложение больше не установлено — см. §5.3);
* пакет AFRd2 не показывается (сам себя переключать не должен, пользы нет).

**Переключатель фильтра** в шапке («Только плееры» ↔ «Все приложения») — страховка на случай,
если конкретный плеер объявил нестандартный тип/схему и в отфильтрованный список не попал.
Это важнее, чем полнота эвристики: пользователь всегда может добраться до любого приложения.

**Сортировка** — `java.text.Collator` по локализованному названию; **иконки** — лениво, в
`getView()`, с кэшем `HashMap<String, Drawable>` (все иконки в память не грузим).

### 4.5. Хранение и настройки

* `Config.itemType`: добавить `switch.skip.pkg` → `TYPE_STR` (`fps.correct.av1.pkg` уже есть).
* `res/xml/preferences.xml`:
  * в группу «Настройки для Android 10 и выше» (`atv14`) добавить строку
    `ru.cobra.zap.xprefs.XAppsPreference` с ключом `switch_skip_pkg`;
  * строку `fps_correct_av1_pkg` в группе «Калибровка частоты по плееру» перевести с
    `XEditTextPreference` на `XAppsPreference` (режим `single`).
* Формат значения: строка пакетов через пробел — ровно то, что читает `strlist_load()`.
  Пустое значение = функция выключена (для `switch.skip.pkg` — «никого не исключаем»).
* Применение — существующим `applyPrefs()` (правки в демоне не нужны).
* **Пометка «не действует» на legacy-пути.** Все ключи, которые демон объявляет как
  `CFGKEY_ATV14` (`switch.skip.pkg`, `fps.correct.enable|list|av1.offset|av1.pkg`) на Android
  6–9 не читаются, но в GUI остаются редактируемыми. Добавляем обратный к `kInactiveOnAtv14`
  список `kInactiveOnLegacy` с этими пятью ключами и новую строку
  `not_applicable_legacy` («не действует на Android 6–9»), затем помечаем их тем же приёмом
  `markInapplicable()`. Это устраняет ложное ожидание «настройка есть — значит работает» и
  не трогает ATV14-поведение.

## 5. Поведение и краевые случаи

1. **Сохранение.** Кнопка «Готово» и аппаратная кнопка Back сохраняют выбор одинаково
   (на пульте это привычнее, чем различие «сохранить/отменить», и исключает потерю работы).
   Отмены без сохранения в этой версии нет.
2. **Пустой список под фильтром** — экран показывает текст «приложения не найдены» и
   подсказку переключить фильтр на «Все приложения»; кнопка «Готово» доступна.
3. **Пакет выбран, но приложение удалено** — показываем строку с именем пакета вместо
   названия и иконки по умолчанию, чтобы его можно было снять. Молча вычищать значение
   нельзя: пользователь мог поставить приложение обратно.
4. **Длинный список** (режим «Все приложения» на боксе с сотней пакетов) — прокрутка
   `ListView`, шапка закреплена; отметки не пересортировывают список на ходу.
5. **Отметка выбранного по умолчанию** — из значения, переданного хостом.
6. **Настройка недоступна на legacy-пути** — ключ живёт в ATV14-группе и помечается
   недействующим на Android 6–9 (см. §4.5), без изменения поведения на ATV14.
7. **Локализация** — все строки в `values/strings.xml` и `values-ru/strings.xml` (по
   существующему образцу: `prefs_*` — заголовок, `prefsum_*` — пояснение, `apps_*` — экран).
8. **Ориентация/DPI** — Activity использует ту же тему (`AppTheme`) и ту же политику
   ограничения шрифта, что `MainActivity` (`limitDpi()` выносится в общий статический
   помощник, чтобы не дублировать код).

## 7. Приёмка

**Сборка и статические проверки**

1. `./mka` — демон без предупреждений, ресурсы (`res/raw`) обновлены; `sh tests/run_tests.sh` — 10/10.
2. `JAVA_HOME=<jdk11> ./gradlew --offline assembleDebug` — APK собирается без предупреждений
   компилятора (`-Xlint` включён в `build.gradle`).

**Живой прогон на стенде `.50` (ATV14)**

3. Установка APK, запуск приложения, вход в «Настройки» → группа «Настройки для Android 10 и
   выше»: строка присутствует, её summary показывает текущее значение (по умолчанию —
   `YouTube TV` из профиля).
4. Нажатие строки открывает экран выбора; в списке (фильтр «Только плееры») присутствуют
   установленные плееры стенда (VLC, OTT Navigator, Plex, YouTube TV), отметка стоит на
   YouTube TV.
5. Снять отметку с YouTube TV, «Готово» → возврат в настройки, summary изменилось; в
   `/data/local/afrd.log` — `config file ... changed, reloading`, при следующем входе в
   конфиг — строка `loading packages: no mode switching` и **без** строки
   `+ com.google.android.youtube.tv`. Отметить два плеера одновременно — summary
   перечисляет оба названия, в ini два пакета через пробел.
6. Воспроизведение 24-фпс ролика в YouTube TV — демон снова переключает режим (ключ пуст);
   вернуть отметку обратно — демон режим не переключает (регресс §28.10 не воспроизводится).
7. **Проверка §28.10 (правка настроек во время воспроизведения):** при играющем видео
   (VLC, удержан режим) изменить список в GUI → после перезагрузки конфига режим должен
   вернуться к исходному, флаг backdoor снят (`debugDisplayModeSetByBackdoor=false`).
8. `fps.correct.av1.pkg` через экран в режиме одиночного выбора: выбрать YouTube TV → в ini
   один пакет; в логе демона — применение поправки AV1 именно к этому пакету.
9. Фильтр «Все приложения» показывает полный список, возврат к «Только плееры» не теряет
   отметки.
10. Пакет, которого нет в системе (добавить вручную в ini, открыть экран) — показывается
    строкой с именем пакета и снимается отметкой.

**Регресс**

11. Legacy-путь (ATV9, `.76`): приложение устанавливается и работает; строка `switch.skip.pkg`
    и ключи `fps.correct.*` помечены «не действует на Android 6–9» и недоступны для правки,
    остальные настройки и запуск демона не изменились; откат — переустановка прежнего APK.
12. `afrd -s`, `status` и остальные пункты настроек не изменились; ни одна существующая
    строка настроек не потеряла значение после первого открытия (проверка ini до/после).

## 9. Открытые вопросы

Нет. Спорные варианты и решения зафиксированы: вариант A (полноэкранный выбор), фильтр
«только плееры» по умолчанию, переиспользуемый интерфейс (`multi`/`single`, задел под
`pkg_value`), отдельная Activity вместо фрагмента (причина — ограничение 1/2 в §3).
