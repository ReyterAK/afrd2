## AFRd2 1.2.0

Автоподбор частоты обновления HDMI под частоту кадров видео для Amlogic.
Форк [AFRd](https://github.com/anpaza/afrd) 0.3.2 (Андрей Заболотный, anpaza), GPL-3.

Выпуск после 1.1.0: AFR «по требованию» (сеанс по кнопке), настоящее «Авто» в
политике дробных частот, проверка фактической частоты дисплея; настройки без
дублей; возврат режима при остановке больше не оставляет рабочий стол на частоте
видео.

### Главное

* **«Зажим» после подъёма закрывается за ~5 с, а не за 14–31 с.** Пока держится
  максимальный режим, огибающая по счётчику кадров ещё не готова; теперь через
  2.5 с (и далее раз в секунду) режим выбирается по данным видео-слоя
  (`switch.bump.probe.ms`, 0 — выключить). Живой замер: максимум держался
  **5347 мс** вместо 14–31 с.
* **OTT Navigator на Android 10+ по умолчанию исключён** (`switch.skip.pkg`): он
  сам управляет частотой через `Surface.setFrameRate`, и подъём/возврат демона с
  ним только конфликтуют. Живая проверка: приложение просит 24.69 Гц, режим 25 Гц,
  подача 24.52 к/с, медиана 40.00 мс, 2 % выбросов. На Android 6–9 AFRd2 работает
  как обычно (собственный AFR плеера там есть, но исключение сделано только для
  нового пути).
* **Исправлено: `switch.skip.pkg` не запрещал смену режима** на новом пути с 1.0.0
  — гейт стоял после быстрого решения, и плеер из списка «AFR мешает» всё равно
  получал переключение. Теперь для него не применяются ни замер, ни быстрое
  решение, ни перепроверка, ни переприменение.
* **AFR «по требованию»**: сеанс по кнопке/команде (`afrd --burst`, API, broadcast)
  — одно переключение и возврат, снова выключено.
* **Политика дробных частот «Авто» стала настоящей**: целая частота берётся только
  при заявленной целой (frame rate hint / frame duration), иначе остаётся дробный
  представитель — 23.976 и 24.000 больше не путаются.
* **Проверка фактической частоты** после смены режима по `vinfo`
  (`sync_duration_num/den`): в журнале видно, что реально получилось на экране.
* **Настройки без дублей**: поправка AV1 и поведение на паузе — по одному пункту;
  ключи, не действующие на текущем пути, скрыты.

### Проверено вживую

* Android 14 (Amlogic S905X5M, ядро 5.15) — новый путь; в том числе сценарий
  «AFR в OTT включён + OTT в `switch.skip.pkg`» и «AFR в OTT выключен, частоту
  ведёт AFRd2» (подъём 24→60→50, короткий спуск 5.3 с).
* Android 9 (UGOOS AM6, ядро 4.9) — legacy-путь: 50 Гц → 24 Гц на старте ролика
  23.976 и возврат на 50 Гц после остановки (`switch.delay.off`).
* Android 11 — новый путь, режим 50 Гц при AFR в OTT включённом.

### Требования и установка

* root (Magisk или встроенный `su` в userdebug-прошивке);
* Amlogic; ядро 5.x — новый путь, ядра 3.14/4.9 — прежний путь AFRd;
* приложение — Android 6.0+ (minSdk 23).

Одновременно должен работать только один экземпляр демона.

* **APK** (интерфейс, настройки, ЧАВО): `ru.reyter.afrd2-1.2.0-release.apk`,
  пакет `ru.reyter.afrd2`. Открыть приложение, дать root и включить автоподбор.
* **Magisk-модуль** (автостарт без приложения): `afrd2-magisk-armeabi-v7a.zip` или
  `afrd2-magisk-arm64-v8a.zip` — Magisk → Модули → «Установить из памяти» →
  перезагрузка. Модуль ничего не пишет в системные разделы.
* **Комплект для ROM-разработчика** (`afrd2-1.2.0-for-rom-dev.zip`): демоны под обе
  ABI, профиль `afrd.ini`, APK и два документа — `afr-on-demand.md` и
  `afr-on-demand-answer-to-rom.md` (ответ на вопрос «зачем ROM-разработчику AFR,
  если AFR умеет сам Android»).

Подробности, ограничения и сборка из исходников — в
[README](https://github.com/ReyterAK/afrd2/blob/master/README.md) и
[ЧАВО](https://github.com/ReyterAK/afrd2/blob/master/FAQ-ru.txt).
